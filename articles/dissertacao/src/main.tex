%
% THREE builds, ONE source, THREE entry files -- and this is the real one; the other two are
% two-line shims that set a switch and read it:
%
%   main.tex           -> the DEFENSE PDF. `make` / `make defense` -> build/main.pdf,
%                         copied to ./dissertacao.pdf. This is the reading copy.
%   main_academico.tex -> the AcademicoPG deposit body. `make academico` ->
%                         build/main_academico.pdf. Sets \ACADEMICOBUILD.
%   main_ppgc.tex      -> the SAME defense PDF plus the approval sheet. `make ppgc` ->
%                         build/main_ppgc.pdf. That is its ONLY difference from main.tex
%                         (author decision 2026-07-28). Sets \APPROVALSHEET.
%
% Each shim holds TWO lines of content, sets one switch and reads this file, so no build can
% drift from another except where a switch says it should. Every build is therefore selectable
% as a compile ROOT in Overleaf or any GUI editor -- which the deposit build was not until
% 2026-07-29, when it existed only as a Makefile command-line injection.
%
% Two switches, both defined below, both following the same \ifdefined pattern so a
% command-line \def works without the nested-\if scanning problem (explained at the switch
% definitions below, which is the one place that hazard is described in full):
%   \ifdefensebuild   front matter on (defense) or off (AcademicoPG deposit)
%   \ifapprovalsheet  approval-sheet placeholder on (ppgc) or off (everything else)
%
% What \ifdefensebuild actually switches (UFV_COMPLIANCE §1): the defense build carries the full
% front matter (cover/folha de rosto, approval placeholder, Resumo/Abstract, lists, sumario);
% the AcademicoPG deposit build starts at the lists, because that system generates
% cover/ficha/resumo/abstract from web forms. The deposit build's body page counter is
% \finalbuildfirstpage below, which keeps its old name deliberately: it is the anchor
% src_utils/mkformat.py extracts the switch region by (its SWITCH_LAST), and the author's rename
% decision covers the switch macro and the external names, not this counter. Flagged, not applied.
%
% DO NOT SELECT THE DEPOSIT BUILD FROM THE COMMAND LINE. A `pdflatex "\newif\ifdefensebuild
% \defensebuildfalse\input{main.tex}"` invocation stood here until 2026-07-29 and silently
% produced the DEFENSE document under a deposit-looking jobname: the command-line \newif is undone
% when this file re-executes \newif\ifdefensebuild below, so the \ifdefined test finds no switch
% macro and the run takes the defense branch. Measured 2026-07-29 by running it verbatim: 108
% pages with the Abstract on rendered page 3, against that day's 105-page deposit build. Compile
% main_academico.tex instead, which is why it exists.
%
% NAMING: this build was called `final` until 2026-07-29 (target `make final`, output
% build/main_final.pdf, switch \FINALBUILD, counter \finalbuildfirstpage). The author renamed
% it `academico` -- src_utils/LATEX_UPGRADE.md §4 A-1/A-2/A-3 -- because "final" says nothing
% next to `defense` and `ppgc`, while "academico" names the system the PDF is uploaded to.
% If you rename it again, sweep the tools that hardcode the stem, because none of them derives
% it: src_utils/build.sh (jobname, the two bibtex calls, the BUILT list, the label map),
% src_utils/sync_page_counts.py (the measured() stem tuple AND its CLAIMS regexes),
% src_utils/sync_deliverables.py (the output-name map), src_utils/mkformat.py and
% src_utils/fastbuild.sh (their target/stem maps), src_utils/verify_format.py (STEMS),
% src/Makefile, and this header. A missed one does not error: it reports the page count of a
% file that is no longer written, or writes a PDF nobody reads.
%
% THE ENVIRONMENT: `make` sets PATH and the three TEXMF variables itself (see the Makefile
% header), so a make build needs no preparation; a bare `pdflatex` run on this machine still
% needs `. ../src_utils/texenv.sh` first. The failure that omission produces is worth naming
% here, because it lies about its own cause and README_SRC.md does not travel with an Overleaf
% paste of src/: with TEXMFVAR wrong, the class and every .tfm resolve, three
% passes run, and pdftex then dies with
%   !pdfTeX error: Font ntx-Regular-tlf-ot1r at 657 not found ==> Fatal error occurred,
%   no output PDF file produced!
% That is NOT a missing font. The .tfm and the .pfb are both present. What is missing is the
% font MAP: newtx registers its ntx-* entries in the usermode updmap output under TEXMFVAR, and
% the system-wide map has none of them. Do not go looking for the font, and do not try to probe
% the variable either -- `kpsewhich -var-value TEXMFVAR` reports an unreadable path on this
% machine, which is why src_utils/texenv.sh sets it explicitly instead of asking.

% Default mode = DEFENSE. main_academico.tex sets \ACADEMICOBUILD (\def\ACADEMICOBUILD{})
% before reading this file; absent that macro, this is the defense build. The macro was
% called \FINALBUILD until 2026-07-29 and was set on the pdflatex command line rather than
% in an entry file; both changed together (LATEX_UPGRADE.md §4).
%
% THE NESTED-\if SCANNING HAZARD, described here once because this is where the pattern
% lives (the header above and README_SRC.md both point at this block rather than repeat it).
% TeX skips the untaken branch of a conditional by SCANNING for the matching \fi, and while
% skipping it still counts every \if... and \fi it passes. It does not evaluate them, so a
% conditional built out of \newif on the command line can leave the scanner counting
% \if tokens that were never meant as a conditional, and the \fi that should close the outer
% test closes an inner one instead. The failure does not look like a switch problem: the
% wrong branch runs, or a \fi is reported missing at a line that has nothing wrong with it.
% \ifdefined\MACRO is a SINGLE conditional primitive with no \newif behind it, so nothing is
% left for the scanner to miscount, which is why both switches below use it. This pattern is
% the fix, NOT the hazard -- a comment here claimed the reverse until 2026-07-29 ("a problem
% that \ifdefined has"), which invited exactly the rewrite that reintroduces the bug.
% Do not "simplify" either line back to \newif manipulation on the command line.
\newif\ifdefensebuild
\ifdefined\ACADEMICOBUILD \defensebuildfalse \else \defensebuildtrue \fi

% Approval sheet: OFF here, ON in main_ppgc.tex (author decision 2026-07-28). See the
% header comment above. main_ppgc.tex sets \APPROVALSHEET before reading this file, so
% the same \ifdefined guard pattern applies, for the reason given at the block above.
\newif\ifapprovalsheet
\ifdefined\APPROVALSHEET \approvalsheettrue \else \approvalsheetfalse \fi

% Page number of the FIRST BODY PAGE in the academico deposit build (the macro keeps the name
% \finalbuildfirstpage; see the NAMING note in the header). UFV_COMPLIANCE §4.4: pre-textual
% pages are counted but not numbered, so the first body page prints
% (number of pre-textual pages) + 1.
%
% THE STANDING HAZARD, and the reason this counter is corrected in every round that touches the
% front matter: it is a hardcoded copy of a MEASURED property of that front matter, so it goes
% silently wrong whenever the front matter changes length, and it is only reachable in the
% academico build (content.tex sets it inside the \ifdefensebuild-false branch), which is why the
% defense and ppgc builds stay correct and nobody notices. Corrected 11 -> 8 in round 6 (the
% deposit build has three fewer pre-textual pages than the defense build, so it had inherited the
% defense offset and every deposited page number ran three ahead) and 8 -> 9 in round 7, when the
% cosine appendix's figure and table pushed the List of Figures and the List of Tables each onto a
% second page and 7 pre-textual pages became 8. Both times the printed number was wrong on the one
% build that is actually deposited, which is a UFV numbering non-compliance.
% MEASURED on the current build, by finding the first page whose header carries a digit:
%   defense   (main.pdf)           physical p.12, prints 12  OK
%   ppgc      (main_ppgc.pdf)      physical p.13, prints 13  OK
%   academico (main_academico.pdf) physical p. 9, printed  8  WRONG before this fix
% HOW TO RE-DERIVE IT, rather than trusting this number: count the pre-textual pages of
% build/main_academico.pdf (they carry no printed number) and add one. src_utils/_round6/
% VERIFY_LIST.md item A4 carries the command, and check.sh runs it, which is how this was caught.
% IF YOU ADD OR REMOVE FRONT MATTER, OR ANY FLOAT THAT LENGTHENS THE LISTS, RE-MEASURE THIS.
\newcommand{\finalbuildfirstpage}{9}
