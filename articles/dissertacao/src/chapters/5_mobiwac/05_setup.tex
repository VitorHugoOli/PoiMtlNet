\section{Experimental Setup}
\label{sec:mobiwac:setup}

This section describes the datasets, data splits, evaluation metrics, statistical tests, and comparison models used in the experiments.

\subsection{Data}
\label{sec:mobiwac:setup-data}
Table~\ref{tab:mobiwac:datasets} summarizes the six datasets. Five datasets come from Gowalla, a location-based social network, and cover the U.S. states of Alabama, Arizona, Florida, Texas, and California~\cite{cho2011gowalla}. The sixth dataset contains check-ins from Istanbul in the Massive-STEPS collection~\cite{wongso2025massivesteps}. We use Istanbul to examine the findings outside the United States.

The U.S. datasets range from about 114,000 check-ins and 1,109 regions in Alabama to about 3.2 million check-ins and 8,501 regions in California. All six datasets use the seven place categories defined in Section~\ref{sec:mobiwac:problem}. The source labels for Istanbul are mapped to these categories. A region is a census tract in the U.S. datasets and a mahalle in Istanbul.

\subsection{Windows, splitting, and the integrity of the representation}
\label{sec:mobiwac:setup-windows}
\emph{Windows.} For each user with at least ten visits, we order the visits by time. We then form overlapping sliding windows of nine visits and use the next visit as the target. A new window starts at each visit, which provides more examples for both tasks. Near the end of a user's history, several start positions can produce shorter, padded windows with the same final visit as the target. We remove these duplicates and keep only the full-length window that ends at this target. The prediction horizon is usually short, but some time gaps are much longer. The median time from the last visit in a window to its target ranges from 0.4 hours in Florida to 5.5 hours in Istanbul. Across the datasets, 5 to 27 percent of the targets occur more than 3 days later.

\emph{Splitting.} We use stratified five-fold cross-validation and split the data by user. All windows from one user remain in the same fold. Therefore, the overlapping windows cannot cross the training and test sets, and the visits of a test user never appear in training. The held-out fold provides the validation data, and we do not reserve a third split. We stratify the split by the next-category label because the seven classes are imbalanced. Food is the majority class in every dataset, ranging from about 25 percent of visits in Florida to 34 percent in Alabama (Table~\ref{tab:mobiwac:datasets}).

\emph{Integrity of the representation.} Before using Check2HGI in the prediction
models, we need to check whether it carries information from the validation data. This
concern exists because the prediction models are trained without the validation users,
but Check2HGI is trained once on the whole dataset and has seen their visits. Check2HGI
does not use the next-category or next-region labels in its training objective. This
reduces the risk, but does not remove it because the observed category of each visit is
an input to the graph. We therefore study two questions: whether training Check2HGI on
the whole dataset changes the results, and whether the graph links between consecutive
visits can bring the next category into the vector used for prediction.

\emph{Whole-dataset training.} The first question is whether using all users to train
Check2HGI gives the prediction models an advantage. To check this, we built a new
representation for each fold using only its training users. We then compared it with the
representation trained on the whole dataset and used the same validation examples for
both. Across Alabama, Arizona, and Florida, neither region Acc@10 nor category macro-F1
changed by more than one third of a point. These differences were smaller than the
variation between folds.

However, this comparison is not the same for the two tasks. For region prediction, we
can compare the region vectors directly. For category prediction, a graph built only
with training users has no vectors for the visits of validation users. Therefore, we
used one vector for each place and kept only the validation windows whose input places
also appeared in training. These windows represent 67 to 87 percent of the validation
data across the three datasets. Thus, the category result applies only to this part of
the data. It does not cover information that is specific to each visit or places that
do not appear in training.

\emph{Links between consecutive visits.} The second question comes from the way the
graph is built. Check2HGI uses information from connected nodes to build each visit
vector, and the graph connects consecutive visits in both directions. In addition, each
visit node contains its observed category. Therefore, the vector for the last visit in
an input window may receive the category of the next visit, which is the target.

To check this possibility, we used a linear classifier to predict the next category
from only the last visit vector in each window. We compared each Check2HGI version with
a clean reference encoder under the same test. We did not use any version that scored
more than three macro-F1 points above this reference, either with raw vectors or after
standardization. One attention-based version was above this limit in both cases, so we
removed it.

However, this test has a limited scope. We performed it once at Florida with five
user-disjoint folds, and it used earlier Check2HGI versions rather than the version used
in the reported results. Also, a linear classifier can miss information that a
nonlinear sequence model could use. For these reasons, the test helps us compare the
versions tested, but it does not prove that the reported representation has no
information from future visits.

For comparison, HGI is also trained once on the whole dataset, while CTLE is trained
separately for each fold using only its training users.

\subsection{Metrics and statistical tests}
\label{sec:mobiwac:setup-metrics}
For the category task, we report macro-averaged F1 (macro-F1). It is the mean of the F1 scores for the seven categories, so each category has equal weight. Its reference point is the majority-class floor, obtained by always predicting the most common category. For the region task, we report accuracy at ten (Acc@10). This measure is the fraction of test visits for which the true region is among the model's ten highest-scoring predictions. If the true region does not occur in the training data for that fold, the visit counts as an error. The reference point for this task is the dedicated model.

A claimed gain and a claimed match require different tests. A non-significant difference does not provide evidence of a match. A written analysis plan, fixed during development and before any result was read, assigned a superiority test to next-category prediction and a non-inferiority test to next-region prediction. These assignments apply to each task across the datasets. The plan did not define a superiority test for next-region prediction. Therefore, the four next-region gains in Section~\ref{sec:mobiwac:results-part2} are secondary results outside the plan.

The plan registered a paired Wilcoxon signed-rank test. With four seeds, its exact one-sided $p$-value cannot be less than $0.0625$. We therefore report a paired $t$-test on the four per-seed means and its 90\% confidence interval for the paired difference. We also report the registered test. The code release includes both tests and documents this departure from the plan.

A \emph{seed} is one complete repetition of the five-fold experiment. It determines the random initialization and the user partition, so each seed produces a different division of the users. Within one seed, the compared models use the same partition. We repeat the experiment across both folds and seeds. Each dataset uses four seeds with five folds per seed, which gives $4\times5=20$ fitted models per configuration. The statistical tests compare the four per-seed means ($n{=}4$). We apply a Holm correction~\cite{holm1979} across the six next-category comparisons and, separately, across the four next-region comparisons.

The non-inferiority claim states that the joint model is no worse than the dedicated model by more than a two-point margin. We test this claim with the two one-sided tests (TOST) procedure~\cite{lakens2017tost}. The analysis plan also fixed the two-point margin in advance. A mobility-aware service acts on which region will be busy, rather than on a single position in the ranking (Section~\ref{sec:mobiwac:problem}). A two-point change in Acc@10 is below the level at which this service would behave differently. Across the four user partitions, the standard deviation of the paired difference ranges from 0.01 to 0.18 points. At Alabama and Arizona, the intervals also support a margin as small as one point (Section~\ref{sec:mobiwac:results-part2}).

\subsection{Baselines}
\label{sec:mobiwac:setup-baselines}
We use the comparison models for three purposes: to compare each task with established methods, to evaluate the representation, and to compare two ways of coupling the tasks.

\emph{Task comparisons.} For next-category prediction, we use POI-RGNN~\cite{capanema2023poirgnn}, which we re-implement from its published architecture and hyperparameters. We also use a Markov model that predicts the category that most often follows the recent categories. We select the best Markov order for each dataset. For region prediction, we compute a Markov-1 floor over region transitions. It uses the same sliding windows and fold splits as our models.

The primary next-region comparison is HMT-GRN~\cite{Lim2022}, an end-to-end recurrent model trained as one unit from the raw check-ins. We evaluate it on the same data, folds, and random initializations. We keep its shared multitask structure and add a region-transition prior that is built from the training data in each fold. We remove the graph components and hierarchical beam search because they support exact next-place prediction, which we do not study. The resulting model predicts region as one of its original targets, but it is not a reproduction of the complete published system.

We also run STAN~\cite{luo2021stan}. We re-implement its published architecture and train it from the raw check-ins with its own representations and sequence construction under one fixed configuration. We adapt its output to rank candidate regions, which are spatial objects compatible with its candidate-distance matching. We do not adapt STAN to category prediction because distance matching does not apply to categories. We report ReHDM~\cite{li2025rehdm} as a reference under its published protocol.

\emph{Representation controls.} Two controls test whether the category gain comes from our representation design rather than from contextualization in general or from additional features. CTLE~\cite{lin2021ctle} is the closest prior contextual check-in representation. We train it end to end at Florida. At Alabama, Arizona, and Istanbul, we keep its weights fixed and do not fine-tune them. The second control adds raw features from each visit to a standard place embedding and uses the same prediction model.

\emph{Task coupling.} Published systems often use a directed cascade that predicts the category first and then conditions place prediction on it~\cite{ye2013nextmove,yu2020catdm,huang2024cslsl}. We test this coupling inside our model instead of re-implementing those systems. We remove the shared trunk, where the two task streams exchange information, and provide the predicted category to the region pathway. The representation, outputs, and training configuration remain unchanged. This comparison isolates the coupling topology, chain or parallel, without increasing the parameter count or computation cost. The chain removes the shared trunk and adds a conditioning projection with about 1,000 parameters.

A final control uses the standard place-level HGI representation~\cite{huang2023hgi} to measure what the per-visit representation adds. All other choices, including the nine-visit window, were fixed during development. The released code provides the full training configuration for every model (footnote~\ref{fn:mobiwac:code}).
