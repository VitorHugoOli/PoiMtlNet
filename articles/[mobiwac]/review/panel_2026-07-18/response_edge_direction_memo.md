# Response-letter memo — R2 leakage question (Check2HGI graph: edge direction, hops, target-visit aggregation)

## (1) Factual answers, with file:line cites

**Edge direction / symmetrization.** Consecutive-check-in ("user_sequence") edges are **undirected by construction**: for each pair of temporally consecutive check-ins (src=earlier, tgt=later) of the same user, BOTH `[src,tgt]` and `[tgt,src]` are appended with the same weight — `research/embeddings/check2hgi/preprocess.py:195-199` (comment "Bidirectional edges", `edges.append([src, tgt]); edges.append([tgt, src])`). The canonical substrate uses only this edge type: `edge_type='user_sequence'` is the default (`preprocess.py:978`, `check2hgi.py:993`) and is what the pipeline pins (`pipelines/embedding/check2hgi.pipe.py:56`). No adjacency-matrix symmetrization step is needed — the edge list is emitted symmetric.

**Edge weights.** `w = exp(-Δt / temporal_decay)` with `temporal_decay=3600 s` default (`preprocess.py:192-193`, default at `preprocess.py:980` / `check2hgi.py` args), then globally min-max normalized to [0,1] over all edges (`preprocess.py:729-732`). Both directions of a pair carry the identical weight (`preprocess.py:198-199`).

**Encoder / hops.** Canonical encoder is `CheckinEncoder`, a plain GCN stack: `num_layers=2` default (`research/embeddings/check2hgi/model/CheckinEncoder.py:16`; `GCNConv` stack at `CheckinEncoder.py:33-36`), instantiated as the canonical "gcn" branch at `check2hgi.py:330` with `--num_layers` default 2 (`check2hgi.py:999`). **Receptive field = 2 hops = up to 2 visits forward AND 2 visits backward** in the user's timeline (plus 2-hop paths through other users is impossible — edges are within-user only — but 2-hop paths through the user's own timeline are).

**Node features contain the category.** `data.x` per check-in = category one-hot ⊕ 4 temporal sin/cos (hour, day-of-week) — `preprocess.py:622-639`.

**Per-visit vector extraction.** After training (unsupervised, full graph), the best checkpoint runs ONE forward pass over the **entire graph** (all check-ins, all edges) and exports every check-in's row to `embeddings.parquet` (`check2hgi.py:862-878`). There is no per-split or causal-masked inference pass.

**Window/target adjacency.** The next-task target is the check-in **immediately following** the last window visit in the user's chronological history (`src/data/inputs/core.py:204-267`: history = `places_visited[start:start+9]`, target = the next position). So the last window visit and the target are temporally consecutive check-ins of the same user → **directly connected by a bidirectional graph edge**.

## (2) Straight answer: can the last visit's vector aggregate the target's features?

**Yes.** Path: the last window visit and the target visit are consecutive same-user check-ins → a symmetric user_sequence edge exists between them (`preprocess.py:195-197`); the first GCN layer therefore mixes the target's node features — **including its category one-hot** (`preprocess.py:623-624`) — into the last visit's representation at 1 hop, and the 2-layer encoder additionally reaches the target+1 visit at 2 hops. Since exported vectors come from a single full-graph forward pass (`check2hgi.py:862-865`), this holds for the vectors actually consumed downstream. (It applies at per-visit granularity, i.e. the check-in-level input to the category head; the region head consumes region-level pooled embeddings where the same information is diluted over all check-ins of a region.)

## (3) What bounds the channel

- **No task supervision routes it.** The substrate is trained by hierarchical contrastive MI (check-in↔POI↔region↔city), never on next-visit labels; nothing optimizes the encoder to preserve or route neighbor-category information into a specific node. The mixing is generic GCN smoothing: degree-normalized, weighted by the min-max-normalized `exp(-Δt/3600)` decay (`preprocess.py:192-193, 729-732`) — the target is one neighbor among a node's full within-user (2-visit-radius) neighborhood, and the same smoothing symmetrically injects PAST visits.
- **Uniform across compared systems.** Every model fed the Check2HGI representation — the dedicated single-task heads AND the MTL model — consumes the identical exported vectors, so all MTL-vs-STL comparative claims difference the channel out. It could only inflate absolute numbers relative to representations that lack it.
- **A4 empirical evidence — what it does and does not cover.** A4 (`scripts/pre_freeze_gates/a4_build.py`, `a4_eval.py`, `a4_cat_eval.py`; `docs/studies/pre_freeze_gates/A4_RESULTS.md`) rebuilds the substrate per fold on **train users only** — validation users' check-in nodes are removed from the graph entirely before preprocessing (`a4_build.py:74`: `~raw["userid"].isin(val_users)`). Result: transductive inflation ≈ 0 on both axes across AL/AZ/FL — reg Δ = −0.33 / +0.01 / −0.12 pp; cat (POI-level proxy, in-coverage 66.8–86.9%) Δ = +0.29 / +0.27 / +0.00 pp, all within fold noise (`A4_RESULTS.md:59-63`). **Coverage caveat:** A4 closes the *cross-user* transductivity channel (val data shaping the substrate) but **does not test the within-user future-edge channel** R2 asks about: (a) in the train-only arm, val users' check-in vectors cannot be produced at all (the "inductive wall", `A4_RESULTS.md:18-19, 54-56`), so A4 evaluates region-level (`a4_eval.py:41-55`) and POI-level (`a4_cat_eval.py` header) representations, not per-visit vectors; (b) the train-only graph still contains all within-user consecutive edges, future ones included. So A4 = strong null on user-level leakage; silent on the within-user channel.

## (4) Drafted response-letter answer (4–8 sentences)

> The reviewer is correct to press on this. The consecutive-check-in edges are stored bidirectionally (both past→future and future→past, with the same normalized exp(−Δt/3600) weight), and the check-in encoder is a 2-layer GCN, so each visit's embedding has a symmetric receptive field of two visits backward and two visits forward in the user's own timeline. Since the prediction target is the check-in immediately following the window, the last window visit's embedding can, in principle, aggregate the target visit's input features — including its category one-hot — through one hop of degree-normalized graph smoothing. We emphasize three points. First, the substrate is trained purely by unsupervised hierarchical contrastive MI and never sees next-visit labels, so no objective routes target information into the preceding visit; the channel is generic bidirectional temporal smoothing, not a task-aligned oracle. Second, the identical exported representation feeds every compared system — the dedicated single-task models and the multi-task model alike — so all comparative (MTL vs. dedicated) conclusions are invariant to this channel; only absolute levels could be affected. Third, our A4 audit, which rebuilds the substrate per fold with validation users' check-ins removed entirely, shows ≈0 inflation on both task axes across three states (reg −0.33…+0.01 pp; category +0.00…+0.29 pp, within fold noise); we note honestly that A4 bounds cross-user transductivity but not this within-user channel, because a train-only graph cannot produce per-visit vectors for held-out users.
